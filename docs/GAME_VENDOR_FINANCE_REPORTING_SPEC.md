# 遊戲商財務與報表指標規格

> 版本：0.1.1
> 更新日期：2026-08-07
> 狀態：報表呈現方向已確認；財務總覽前端原型已建立

## 1. 產品定位

遊戲商財務是 Provider 對自己遊戲營運結果的財務統計，不是 GGAP 的平台財務、代理商結算或會員錢包。

Provider 財務報表的資料來源是 Provider 保存的 Game Round；GGAP 的平台比對與最終結算由財務或 GGAP 端執行。

## 2. 與 GGAP 的責任邊界

| 項目 | Provider Portal | GGAP |
|---|---|---|
| 遊戲投注與派彩紀錄 | 保存與統計 | 傳入脈絡、保存平台側紀錄 |
| Provider 點數 | 定義與統計 | 不改寫 Provider 規則 |
| USDT | 保存對接換算結果 | 對接與下游換算 |
| Provider 財務 | 提供報表 | 讀取或比對 |
| 平台財務 / 結算 | 不負責 | 負責 |
| 對帳狀態 | 不在本報表呈現 | 財務流程處理 |

## 3. 報表種類

### 3.1 遊戲商財務總覽

目前前端原型頁面見 [`GAME_VENDOR_FINANCE_OVERVIEW_SPEC.md`](./GAME_VENDOR_FINANCE_OVERVIEW_SPEC.md)，路由為 `/finance`。該頁目前以正式環境 mock data 展示畫面與規格骨架，尚未接入正式 API。

顯示指定時間區間的：

- 投注總額
- 派彩總額
- 淨輸贏
- GGR
- 投注筆數
- 玩家人數
- 平均投注額
- 人均投注額
- 點數與 USDT 對照

### 3.2 代理商 × 遊戲彙總

這是主要對外資料確認報表，以代理商作為查詢出發點，再依遊戲整合：

| 欄位 | 說明 |
|---|---|
| 代理商 | GGAP 傳入的代理商識別 / 顯示名稱 |
| 遊戲 | 遊戲 ID、名稱、類型 |
| 投注筆數 | 有效 Game Round 數量 |
| 玩家人數 | 不重複會員數 |
| 投注總額 | Provider 點數；可展開 USDT |
| 平均投注額 | 投注總額 ÷ 投注筆數 |
| 人均投注額 | 投注總額 ÷ 玩家人數 |
| 輸贏 | 依核准正負方向顯示 |
| GGR | Provider 定義的 GGR |

### 3.3 Game Round 財務明細

從聚合數字進入單筆明細，顯示 Game Round、點數、USDT、代理商、會員脈絡與結算狀態。此頁不取代 Game Round 明細查詢，而是提供財務檢視入口。

## 4. 金額呈現原則

- 主要列表以 Provider 點數為主。
- 使用者點擊數字或展開欄位時，顯示換算後 USDT。
- 欄位標題旁提供 info tooltip，說明公式、統計時間與換算規則。
- 匯出檔案同時包含點數與 USDT 欄位。
- 金額需顯示精度、幣別與時間區間。
- 同一筆 Game Round 的 USDT 使用當次保存的換算結果，不使用目前最新規則覆蓋歷史結果。

## 5. 統計時間與資料範圍

- 預設使用 `settled_at`。
- 正式財務報表預設只統計 `environment=production`。
- DEMO 可實際遊玩，但其 Game Round 應獨立顯示，不能混入正式投注、輸贏或 GGR。
- 測試環境資料只供測試與監控，不能進入正式財務統計。
- 只有有效結算的 Game Round 進入一般財務彙總。
- 取消、失敗、重複、回滾資料需依狀態另列或排除。
- 匯總查詢必須套用 Provider 隔離與使用者權限。
- 報表需要明確標示時區與查詢區間。

## 6. 公式

| 指標 | 公式 |
|---|---|
| 投注總額 | `SUM(bet_points)` |
| USDT 投注總額 | `SUM(bet_usdt)` |
| 平均投注額 | 投注總額 ÷ 投注筆數 |
| 人均投注額 | 投注總額 ÷ 不重複玩家人數 |
| 淨輸贏 | `SUM(net_result_points)`；目前老虎機與單人 Crash 的單局公式為 `payout_points - bet_points` |
| GGR | 依 Provider 核准的 GGR 定義 |

若分母為 0，API 應回傳明確的 null / zero 語意，前端統一顯示 `-`，不可出現 Infinity 或 NaN。

## 7. 對帳邊界

本報表不提供：

- 已匹配
- 資料不一致
- 待處理
- GGAP 差異金額
- 對帳批次狀態

Provider Portal 的責任是產出一致、可追溯的 Provider 數據；實際與 GGAP 比對由財務或 GGAP 執行。若 Provider 偵測到自身資料異常，應以監控告警或資料品質狀態呈現，不冒充 GGAP 對帳結果。

## 8. 匯出規格草案

匯出至少包含：

- 報表產生時間與時區
- 查詢時間區間
- 代理商 ID / 名稱
- 遊戲 ID / 名稱 / 類型
- 投注筆數、玩家人數
- 點數投注、點數派彩、點數輸贏、點數 GGR
- USDT 投注、USDT 派彩、USDT 輸贏、USDT GGR
- 平均投注額、人均投注額
- 使用的換算規則版本或報表資料版本

匯出需受權限與最大資料量限制；大範圍匯出可採非同步產檔並透過通知中心告知完成。

## 9. 權限建議

| 角色 | 查看 | 匯出 | 公式 / 換算規則 | 修改資料 |
|---|---:|---:|---:|---:|
| 管理員 | 是 | 是 | 是 | 依權限 |
| 營運 | 是 | 是 | 查看 | 否 |
| 財務 | 是 | 是 | 是 | 否或依流程 |
| 風控 | 依範圍 | 依權限 | 查看 | 否 |

正式角色與 permission key 需由 Provider 團隊確認。

## 10. 待確認事項

- GGR 與 `net_result_points` 的關係、正式定義與正負方向。
- 點數與 USDT 的精度、匯率 / 規則來源與四捨五入。
- 報表資料快照與重算策略。
- 匯出格式（CSV、XLSX）與單次上限。
- 財務月結或日結是否需要鎖定版本。
- DEMO 是否需要獨立的財務樣式報表，以及其沙盒點數的顯示方式。
