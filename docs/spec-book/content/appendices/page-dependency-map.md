# 第一階段跨頁依賴圖

本章說明 21 個本輪頁面如何共用產品主資料、業務紀錄、聚合口徑、狀態與發布輸入。箭頭代表「規格與資料依賴」，不是 runtime API 呼叫順序，也不表示使用者必須照箭頭操作。

## 閱讀規則

- 節點可連回對應頁面規格；群組節點可能包含多個內容頁。
- 每條依賴都必須說明上游輸出、下游用途及不可違反的 guardrail。
- 「邊界已確認」只表示責任與資料方向已清楚，不代表 schema 或 API 已核准。
- 「契約待補」表示頁面關係合理，但欄位、狀態、同步或錯誤處理仍需正式定義。
- 同一頁可出現在多條鏈，例如遊戲紀錄同時是財務來源與風控追溯終點。

## 使用方式

1. 撰寫某頁前，先確認它需要哪些上游輸入，以及下游會使用哪些輸出。
2. 共用資料不可在下游頁面重新定義不同公式、狀態或環境範圍。
3. 「契約待補」的箭頭應轉成共用 TBD；不得在每頁各自發明一套欄位。
4. 上游規格變更時，依本圖檢查所有下游頁面、API、測試與驗收條件。
5. Deferred 契約取得後，先更新責任邊界及共用契約，再回填受影響頁面。
