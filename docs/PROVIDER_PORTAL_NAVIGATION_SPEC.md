# Provider Portal 導覽列與頁面範圍規格

> 版本：0.4.0
> 更新日期：2026-08-13
> 狀態：第一至六階段導覽、路由、儀表板與監控／風控獨立 mock 原型、文件地圖與整體驗證已完成；正式 API、權限、監控門檻與更新頻率待確認

## 1. 導覽目標

新版導覽只呈現遊戲商需要管理的工作，不把 GGAP 平台的代理商、商戶、會員與錢包功能搬回 Provider Portal。

頁面實作順序為：先完成左側導覽、路由與頁面範圍；尚未製作的頁面可以先顯示空白或佔位內容，避免用舊頁面語意誤導規格討論。

## 2. 目標主導覽

| 順序 | 導覽名稱 | 建議 route | 主要目的 |
|---:|---|---|---|
| 1 | 總覽 | `/dashboard` | 查看 Provider 營運摘要與健康狀態 |
| 2 | 遊戲管理 | `/games` | 管理遊戲主資料與全域狀態 |
| 3 | 數據與報表 | `/reports` | 查詢 Game Round 與聚合統計 |
| 4 | 遊戲商財務 | `/finance` | 查看 Provider 自己的財務統計 |
| 5 | 遊戲監控與風控 | `/monitoring` | 查看遊戲、請求與異常狀態 |
| 6 | GGAP 對接 | `/ggap` | 查看連線、同步與對接事件 |
| 7 | 通知中心 | `/notifications` | 處理 Provider 系統通知 |
| 8 | 官方網站 | `/website` | 管理遊戲官網與遊戲大廳內容 |
| 9 | 系統設定 | `/settings` | Provider 使用者、權限與系統設定 |

完整階層、32 個內容頁的 route、頁面責任與原型狀態，集中記錄於 [`PROVIDER_PORTAL_PAGE_MAP.md`](./PROVIDER_PORTAL_PAGE_MAP.md)。

## 3. 子頁範圍

### 3.1 總覽

- Provider 遊戲數與上下架摘要
- 近期投注、GGR、玩家數
- GGAP 連線健康
- Game Round / 結算異常
- 未讀通知摘要

### 3.2 遊戲管理

- 遊戲列表
- 遊戲版本
- 遊戲設定
- 數值設定
- 遊戲素材
- 環境與發布
- 全域上下架與維護

遊戲列表的詳細欄位、環境狀態、Release 顯示、RTP Tips、篩選與互動方向，見 [`GAME_LIST_SPEC.md`](./GAME_LIST_SPEC.md)。

「環境與發布」負責正式環境與官網 DEMO 的上架、下架、維護及已部署版本啟用；測試環境只提供部署版本與健康監控，不提供操作按鈕。

DEMO 可以實際遊玩，但必須使用隔離的 DEMO / 沙盒資料，不得連到 GGAP 正式會員錢包、代理商帳務或正式結算。

不包含代理商個別開關；該能力屬 GGAP 平台側。Provider 可以看到同步狀態或平台回報，但不以 Provider 主資料頁控制代理商。

### 3.3 數據與報表

- 遊戲紀錄（單筆 Game Round）
- Game Round 查詢與匯出
- 報表匯出

遊戲紀錄頁只查詢正式環境，一列代表一筆 Game Round；詳細欄位、查詢、排序與匯出規則見 [`GAME_ROUND_RECORDS_SPEC.md`](./GAME_ROUND_RECORDS_SPEC.md)。

DEMO 使用統計與 QA / 送測紀錄後續獨立製作，不與遊戲紀錄或正式彙總報表合併。

報表主要顯示 Provider 點數，可展開 USDT；不顯示 GGAP 對帳匹配狀態。

### 3.4 遊戲商財務

- 遊戲商財務總覽
- 投注與輸贏彙總
- GGR 統計
- 由「遊戲紀錄」承接單筆 Game Round 詳情入口
- 匯出記錄

不建立獨立的 Game Round 財務明細頁；單筆詳情沿用 `/reports`「遊戲紀錄」。不包含 Provider wallet、會員錢包、代理商結算或 GGAP 對帳批次。

### 3.5 遊戲監控與風控

- 監控總覽
- 風控報表：查詢與分析 Risk Event，唯讀導向處理
- 風控告警／處理：告警工作佇列、人工覆核、隔離與 GGAP 通知操作
- Game Round 異常
- 遊戲健康 / 服務狀態
- GGAP 請求與結算錯誤
- 風控告警與案件
- 規則設定（若確認由 Provider 管理）

### 3.6 GGAP 對接

- Provider 連線狀態
- 遊戲目錄同步
- 啟動 / 結算請求紀錄
- 回呼與錯誤紀錄
- 重試 / 補單狀態
- 對接設定與 API credentials（敏感值需遮罩）

### 3.7 通知中心

- 全部通知
- 未讀通知
- 依類型篩選
- 通知偏好

詳細規格見 [`NOTIFICATION_SPEC.md`](./NOTIFICATION_SPEC.md)。

### 3.8 官方網站

- 官網遊戲展示
- 公告與內容區塊
- 圖片 / 資產
- 發布狀態

活動功能先不列入第一階段；若未來加入，需確認是官網內容活動還是遊戲內活動。

### 3.9 系統設定

- Provider 使用者
- Provider 角色與權限
- API key / 對接憑證
- 操作紀錄
- 通知偏好
- 語系與時區

## 4. 暫時移出主要導覽

下列舊版頁面不列入新版主導覽：

- Aggregator / 平台管理
- 代理商管理
- 商戶管理
- 會員管理
- Provider 錢包 / API wallet
- 舊交易事件報表
- 平台結算與對帳報表
- 獨立 Jackpot 管理
- 代理商 / 商戶 Portal 切換器

舊頁面可以保留在程式中作為參考，但不應繼續新增功能或被新版選單連結。

## 5. 舊原型對應策略

| 舊功能 | 新版策略 |
|---|---|
| `/games/*` | 保留概念，移除 merchant access，改為 Provider 主資料 |
| `/games/environments` | 新增環境與發布頁，管理正式 / DEMO，測試只讀監控 |
| `/reports/*` | 改寫成 Game Round 與 Provider 聚合報表 |
| `/finance/*` | 改寫成遊戲商財務 |
| `/risk/*` | 改寫成遊戲監控與 Provider 風控 |
| `/aggregators/*` | 改寫成 GGAP 對接 |
| `/jackpots/*` | 從主導覽移除，未來有跨機台需求再重開規格 |
| `/agent/*`、`/merchant/*` | 從 Provider 主流程移除 |
| `/platforms/*`、`/players/*` | 從 Provider 主流程移除 |

## 6. 第一至六階段完成狀態

第一至六階段目前完成：

1. 左側導覽群組與名稱。
2. 新版 route 骨架與 32 個可進入內容頁。
3. 既有完成頁面保留原型內容。
4. 8 個缺少正式內容的頁面共用 Provider Placeholder mock blueprint；儀表板、監控總覽、風控報表與風控告警／處理已改由獨立內容頁承接。
5. Placeholder 頁面的功能說明、責任範圍、主要內容、展示資料、空資料狀態與 API 待接標示。
6. 遊戲紀錄、DEMO環境數據與代理商 × 遊戲彙總的導覽名稱統一。
7. 頁面地圖、產品規格、轉移索引與 handoff 文件已同步。
8. 已完成主要 route、24 個內容頁、8 個 Placeholder、桌機／手機版、console 與文件一致性的整體驗證。
9. 風控報表與風控告警／處理完成 mock query、操作狀態、跨頁導向與響應式原型。

後續才依產品、GGAP 與後端規格逐頁填入正式資料與互動。

## 7. 導覽驗收條件

- 左側只出現九個新版主群組。
- 舊代理商、商戶、會員、平台、Jackpot 項目不出現在主要導覽。
- 每個內容頁都有可進入的 route，已完成頁面保留原型內容，未完成頁面顯示明確 Placeholder。
- 目前未完成頁面不顯示與責任邊界衝突的舊功能。
- 桌機與窄版畫面不發生文字、圖示或選單重疊。
- 導覽名稱、route、文件與權限 key 保持一致。

## 8. 目前原型驗收範圍

- 共用 Placeholder 的 8 個 route 均配置群組專屬 mock blueprint，包含環境與發布、GGAP 對接與通知內容區塊。
- 儀表板使用獨立內容頁，直接從即時狀態、營運數據、趨勢與待處理事項開始，不顯示 Placeholder 說明區塊。
- 遊戲列表、遊戲紀錄、財務總覽、代理商 × 遊戲彙總、遊戲官網與遊戲大廳沿用既有原型頁，不被 Placeholder 覆蓋。
- 監控總覽、風控報表與風控告警／處理使用獨立完整內容頁；三頁均直接從主要工作內容開始，不顯示重複 Hero、頁面資訊或 blueprint。
- 不接正式 API，不在 Placeholder 階段實作正式資料流、權限或操作副作用。
- 第五階段的主要 route、桌機／手機版、console 與導覽文件一致性驗證已完成。
