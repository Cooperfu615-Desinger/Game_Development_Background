01 · 基礎規格

產品定位與目標

Provider Portal 的產品定位、使用者、核心任務與目前階段。

草案
章節編號01
規格狀態草案

Provider Portal 是 GGAP 的其中一個 Provider Portal，服務對象為遊戲商內部團隊。它不是另一套遊戲聚合平台，也不是代理商、商戶或會員後台。

核心任務

  1. 管理遊戲商自己的遊戲產品、版本、規則、數值與素材。
  2. 接收 GGAP 傳入的遊戲請求與業務脈絡。
  3. 保存可追蹤、不可任意改寫的 Game Round。
  4. 產生遊戲商自己的數據、財務、監控與風控報表。
  5. 管理遊戲官網、遊戲大廳與 Provider 內部設定。

主要使用者

Provider Portal 只服務同一個 Provider 內部人員。正式角色預計拆分為營運、財務、風控、技術與管理員；所有角色仍以同一個 provider_id 為資料邊界。

目前產品階段

  • 目前重點是畫面、資訊架構與規格骨架。
  • 32 個內容頁中，24 個已有內容原型，8 個仍使用 Placeholder。
  • 正式 API、權限、資料流、狀態碼、精度與警戒門檻尚未整體核准。
  • Prototype / Mock data 只用於確認資訊架構與欄位方向。

不在目前範圍

  • Provider、代理商或會員錢包。
  • 代理商、商戶、會員主資料管理。
  • GGAP 平台交易、平台結算與平台對帳。
  • 代理商逐一開關遊戲的 Provider 控制台。
  • 獨立跨機台 Jackpot 管理。
  • Provider 專屬活動、官網活動與遊戲內活動管理。

產品成功條件

  • 每個頁面都能清楚回答使用者目的、資料來源、操作邊界與下一步。
  • 前端可直接取得欄位、狀態、互動與錯誤呈現規則。
  • 後端可直接取得資料模型、查詢、權限、冪等與錯誤契約。
  • QA 可由同一份規格形成可驗證的測試案例。
