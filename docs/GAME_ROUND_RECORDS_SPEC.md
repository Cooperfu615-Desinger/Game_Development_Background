# Provider Portal 遊戲紀錄頁規格

> 版本：0.1.0
> 更新日期：2026-08-05
> 狀態：工作規格，供原型開發與後續前後端討論使用

## 1. 頁面定位

本頁是 Provider Portal 的「遊戲紀錄」頁面，資料來源為 Provider 保存的單筆 Game Round。

一列代表一筆 Game Round，不在本頁混合彙總統計、Demo 使用數據或 QA 測試數據。

本頁主要用途：

- 查詢正式環境的單筆遊戲紀錄。
- 依 Provider 與 GGAP 識別碼追查紀錄。
- 查看代理商、會員、遊戲與結算金額脈絡。
- 查看遊戲商點數與對應 USDT 金額。
- 查看單筆紀錄詳情。
- 匯出完整 Excel 或 CSV 檔案。

Game Round 的資料模型、報表公式與跨功能原則，另見 [`GAME_ROUND_AND_REPORTING_SPEC.md`](./GAME_ROUND_AND_REPORTING_SPEC.md)。

## 2. 本頁資料範圍

### 2.1 本階段包含

- 正式環境 `production` Game Round。
- 老虎機與目前單人迷你遊戲的單筆結算紀錄。
- 查詢條件、欄位排序、單筆詳情與匯出。
- Provider 點數為主要顯示金額。
- USDT 金額於詳情與匯出提供。

### 2.2 本階段不包含

- DEMO 使用統計。
- QA / 送測環境紀錄。
- 代理商 × 遊戲彙總報表。
- 遊戲商財務彙總與 GGR 報表。
- 商戶資料顯示或商戶查詢。
- Provider 權限與會員 ID 遮罩。
- 棋牌特殊結算規則。
- 多人玩法的共享局號與參與者資料。

DEMO 與 QA 環境後續以獨立頁面或報表處理，不與遊戲紀錄混合。

## 3. 正式環境規則

- 本頁後端查詢固定帶入 `environment=production`。
- 主列表不顯示環境欄位，頁面標題或頁面資訊可標示「正式環境」。
- `environment` 仍需保留在資料模型與匯出資料中，作為資料來源識別。
- Demo、QA、開發環境資料不得出現在本頁。
- 正式 Game Round 才能進入正式遊戲商數據與財務報表。

## 4. 主要列表

### 4.1 欄位順序

| 順序 | 顯示欄位 | 對應資料 | 說明 |
|---:|---|---|---|
| 1 | 序號 | 前端計算 | 只供列表閱讀，不是資料庫欄位，不可作為查詢識別。 |
| 2 | 結算時間 | `settled_at` | 格式為 `YYYY-MM-DD HH:mm:ss`，主要時間欄位。 |
| 3 | Provider Game Round ID | `round_id` | Provider 端唯一識別。 |
| 4 | GGAP Round ID | `external_round_id` | GGAP 傳入或對應的外部局號。 |
| 5 | 遊戲 ID | `game_id` | Provider 遊戲識別。 |
| 6 | 遊戲名稱 | `game_name` | 當時的遊戲名稱快照。 |
| 7 | 遊戲類型 | `game_type` | 例如 `slots`、`crash`、`table`。 |
| 8 | 遊戲版本 | `game_version` / `release_id` | 該筆 Game Round 實際使用的版本。 |
| 9 | 代理商 ID | `agent_id` | GGAP 傳入的代理商識別。 |
| 10 | 代理商名稱 | `agent_name` | 代理商名稱快照或查詢結果。 |
| 11 | 會員 ID | `member_id` | GGAP 傳入的會員識別。 |
| 12 | 投注額 | `bet_points` | 以 Provider 遊戲點數顯示。 |
| 13 | 派彩額 | `payout_points` | 以 Provider 遊戲點數顯示。 |
| 14 | 玩家淨輸贏 | `net_result_points` | 以 Provider 遊戲點數顯示，正負號需清楚呈現。 |
| 15 | 結算狀態 | `status` | 顯示 Game Round 業務狀態。 |
| 16 | 操作 | - | 提供單筆「詳情」入口。 |

GGAP 幣別不列入主要列表，於單筆詳情與匯出提供。正式環境現階段固定以 `USDT` 為對接標準。

### 4.2 序號規則

- 序號由前端依目前查詢結果計算。
- 分頁時可延續顯示，例如第二頁從 11 開始。
- 序號不可排序、不可篩選、不可作為資料識別。
- 序號不列入正式資料模型；匯出時不需包含序號。

### 4.3 時間顯示

- 主要列表顯示 `settled_at`。
- `settled_at` 尚未產生時顯示 `—`。
- `started_at` 僅在單筆詳情顯示；老虎機與單人迷你遊戲可為空。
- `created_at` 與 `updated_at` 屬技術追蹤欄位，於詳情顯示。
- API 應保留可辨識時區的時間格式；原型畫面統一顯示年月日、時、分、秒。

## 5. 查詢條件

主要查詢條件保持精簡：

| 條件 | 查詢方式 |
|---|---|
| 時間區間 | 依 `settled_at` 查詢。 |
| 遊戲名稱 | 可同時支援遊戲名稱或遊戲 ID。 |
| 代理商 | 可同時支援代理商名稱或代理商 ID。 |
| Provider Game Round ID | 支援精確查詢。 |
| GGAP Round ID | 支援精確查詢。 |
| 會員 ID | 支援精確或文字查詢。 |
| 結算狀態 | 查詢處理中、已結算、取消、回滾或失敗紀錄。 |

不提供商戶、環境、幣別或平台錢包相關篩選條件。

時間區間的預設值、最大查詢範圍與分頁上限，先保留給後端 API 契約確認；原型可先使用適合展示的預設區間。

## 6. 排序規則

- 預設依 `settled_at` 降冪排序，最新結算紀錄在最上方。
- `settled_at` 為空的處理中紀錄排在已結算時間之後。
- 使用者可以點擊可排序欄位標題切換升冪／降冪。
- 可排序欄位至少包含結算時間、Provider Game Round ID、GGAP Round ID、遊戲、代理商、會員 ID、金額與結算狀態。
- 序號與操作欄不可排序。
- 排序應由後端依查詢參數處理，不只排序目前前端頁面的資料。
- API 需使用穩定的 tie-breaker，避免同一排序值造成分頁資料跳動。

目標查詢形式可參考：

```text
GET /api/provider/v1/game-rounds?sort_by=settled_at&sort_order=desc
```

實際 API 路徑、參數命名與分頁格式待後端確認。

## 7. Game Round 狀態

原型先使用以下狀態語意：

| 程式值 | 顯示名稱 | 說明 |
|---|---|---|
| `processing` | 處理中 | 尚未完成遊戲結算。 |
| `settled` | 已結算 | 已完成遊戲結果與金額結算。 |
| `cancelled` | 已取消 | 該局取消，不形成有效結算。 |
| `rollback` | 已回滾 | 原本已結算，後續因明確原因沖回。 |
| `failed` | 結算失敗 | 結算流程發生錯誤，需要追查或補處理。 |

狀態與遊戲上架狀態、GGAP 同步狀態分開處理。

一般正式報表只計入有效的 `settled` Game Round；取消、回滾與失敗資料仍須保留並可查詢。

## 8. 單筆詳情

詳情頁或詳情 Dialog 至少分為以下區塊：

### 8.1 Game Round 與 GGAP 識別

- Provider Game Round ID。
- GGAP Round ID。
- Request ID。
- 結算狀態與狀態說明。

### 8.2 遊戲資訊

- 遊戲 ID。
- 遊戲名稱。
- 遊戲類型。
- Game Version / Release ID。
- 遊戲數值或限紅規則版本，若資料存在。

### 8.3 GGAP 脈絡

- 代理商 ID 與名稱。
- 會員 ID。
- GGAP 幣別。

Provider Portal 不顯示商戶。後端若因 GGAP 追蹤需要保存 `merchant_id`，仍屬隱藏的技術快照，不作為 Provider UI、查詢或報表維度。

### 8.4 時間與金額

- 開始時間（若有）。
- 建立時間。
- 結算時間。
- 最後更新時間。
- 投注額、派彩額、玩家淨輸贏點數。
- 投注額、派彩額、玩家淨輸贏 USDT。
- 點數與 USDT 換算比例或換算規則版本。

### 8.5 異常資訊

若狀態不是 `settled`，可顯示：

- 失敗原因。
- 取消原因。
- 回滾原因。
- 重試或補處理資訊。

原型階段可先使用預留區塊與 mock 資料；完整原始請求、回應與事件歷程留待 GGAP 對接完成後補充。

## 9. 金額呈現

目前老虎機與單人迷你遊戲採用同一套原型呈現方式：

```text
淨輸贏 = 派彩額 - 投注額
```

例如：

```text
投注額：100 點
派彩額：80 點
玩家淨輸贏：-20 點
```

規則如下：

- Provider 點數是主要列表顯示值。
- USDT 金額在詳情顯示，匯出時一併提供。
- 換算結果需保存當次使用的換算規則，不使用最新規則覆蓋歷史紀錄。
- 金額計算由後端或 mock API 提供，前端不自行推算歷史結果。
- 原型先不處理棋牌可能存在的本金返還差異。

## 10. 匯出

提供兩種格式：

- Excel（`.xlsx`）
- CSV（`.csv`）

匯出依目前查詢條件產生，內容比主列表完整，至少包含：

- Provider Game Round ID。
- GGAP Round ID。
- 遊戲 ID、名稱、類型與版本。
- 代理商 ID 與名稱。
- 會員 ID。
- `environment=production` 資料來源欄位。
- GGAP 幣別。
- 開始、建立、結算與最後更新時間。
- 投注、派彩、玩家淨輸贏點數。
- 投注、派彩、玩家淨輸贏 USDT。
- 換算比例或換算規則版本。
- 結算狀態與異常說明。

不匯出前端顯示用序號，也不匯出商戶欄位。

原型階段可先使用同步匯出；大量資料的非同步匯出、匯出任務紀錄與通知留待後續。

## 11. 原型驗收條件

- 頁面只顯示正式環境 Game Round。
- 一列只代表一筆 Game Round。
- 結算時間顯示到秒，預設由新到舊。
- Provider Game Round ID 與 GGAP Round ID 為獨立欄位。
- 遊戲 ID、名稱、類型與版本可清楚查看。
- 代理商顯示於主要列表，商戶不出現在 Provider UI。
- 主要金額以 Provider 點數顯示。
- 詳情可以查看 USDT 與換算資訊。
- 查詢條件符合本文件第 5 節。
- 可依主要資料欄位排序。
- 可開啟單筆詳情。
- 可以匯出 Excel 與 CSV。
- Demo、QA、彙總報表與權限功能不混入本階段。

## 12. 後續待確認

- 正式 API 路徑、分頁、排序與錯誤格式。
- `status` 的正式枚舉與回滾／補單流程。
- USDT 精度、換算方向與四捨五入規則。
- 時間儲存時區與報表時區。
- 詳情中的原始請求、回應與事件歷程。
- DEMO 使用統計與 QA 送測紀錄的獨立頁面。
- 棋牌與多人玩法的結算模型。
