## 治理規則

- TBD 不等於 Deferred：TBD 是內容未決；Deferred 是頁面尚未排入本輪。
- 優先級是目前規格整理工作的建議層級，不代表已核准的產品時程。
- P0 必須在對應正式資料、API、高風險流程或上線前解決；不代表所有 P0 都阻擋 UI 骨架。
- 每項 TBD 必須連到受影響頁面或業務鏈，避免相同問題在不同頁面重複決策。
- 決議後不直接刪除項目；應更新狀態、決議內容、日期與取代的規格版本。
- Deferred 模組相關問題只記錄需要取得的外部輸入，不藉此建立其畫面或 API 草案。

## 決議完成條件

一項 TBD 只有在以下條件成立後才能視為完成：

1. 決策責任方已確認結論，且能指向正式規格、schema、ADR 或會議決議。
2. 受影響頁面、共用章節、資料字典、enum、API 與測試已同步更新。
3. 若改變既有原型，已明確決定修原型或保留相容策略。
4. 阻擋範圍已解除，或剩餘限制已轉成新的具體 TBD。
5. 版本紀錄已記載決議日期、影響範圍與取代內容。
