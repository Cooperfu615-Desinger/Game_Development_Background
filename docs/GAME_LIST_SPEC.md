# Provider Portal 遊戲列表工作規格

> 版本：0.2.0
> 更新日期：2026-08-18
> 狀態：目前需求基準；已同步 Decision Pack 03，正式 API 命名與權限待實作 Mapping

本文件定義 Provider Portal「遊戲列表」頁面的資訊架構、顯示規則與互動方向。Game、Version、Artifact、Release、三環境晉級與全域可用性的共用語意，以 [`Decision Pack 03｜遊戲版本與發布生命週期`](./spec-book/content/appendices/decision-pack-03-game-release-lifecycle.md) 為上游；環境與發布頁負責實際操作與歷程。

## 1. 頁面定位

遊戲列表是 Provider 遊戲營運的總覽入口，主要目的為：

- 快速查看 Provider 所有遊戲
- 同時比較正式、DEMO 與測試環境的目前版本與狀態
- 查看正式 / DEMO RTP 摘要
- 查看 Provider 全域可用性與 GGAP 目錄 / Release 同步狀態
- 透過版號、狀態與詳情入口前往對應頁面

遊戲列表不直接承擔完整版本設定、RTP 設定、限紅設定或素材上傳操作。

## 2. 列表範圍

- 顯示 Provider 的所有遊戲，包含尚未上線、尚未部署或尚未啟用的遊戲。
- 顯示獨立的 Provider 全域可用性；不得從 Production Release 狀態反推是否已全域上架。
- 遊戲是否可接受新 Launch，需同時符合全域可用性、Production Active Release、Provider 維護／隔離及 GGAP 代理商開放條件。
- 不在遊戲列表管理代理商或商戶個別開關。
- 不在遊戲列表顯示素材上傳結果。

## 3. 欄位與順序

桌機版預設欄位順序如下：

| 欄位 | 顯示內容 |
|---|---|
| 遊戲代號 | Provider 遊戲識別 |
| 遊戲名稱 | 遊戲展示名稱 |
| 類型 | `slots`、`crash`、`table` 等遊戲類型 |
| 正式版號 | 正式環境目前生效的 Release |
| 正式狀態 | 正式環境狀態 |
| 正式 RTP | 正式環境實際 RTP 摘要，標題旁提供 Tips |
| DEMO 版號 | DEMO 環境目前生效的 Release |
| DEMO 狀態 | DEMO 環境狀態 |
| DEMO RTP | DEMO 環境實際 RTP 摘要，標題旁提供 Tips |
| 測試版號 | RD / 測試環境目前部署版本 |
| 測試狀態 | 測試環境部署狀態 |
| 全域可用性 | Provider 對所有通路生效的上架、維護、暫停或退役狀態 |
| GGAP 同步 | 遊戲目錄 / Release 同步狀態 |
| 操作 | 固定提供「詳情」入口 |

## 4. 表頭呈現

桌機版建議使用兩層群組表頭：

第一層：

```text
遊戲資訊 | 正式環境 | DEMO 環境 | 測試環境 | 全域可用性 | GGAP 同步 | 操作
```

第二層：

```text
遊戲代號 | 遊戲名稱 | 類型
目前生效版號 | 狀態 | RTP
目前生效版號 | 狀態 | RTP
目前部署版號 | 狀態
狀態
同步狀態
詳情
```

列表以桌機寬表格為第一階段設計目標，暫不處理手機版配置。

## 5. 環境狀態

### 5.1 正式與 DEMO

正式與 DEMO 的主要狀態顯示 Release 結果，不與全域可用性共用欄位：

- `已生效`
- `發布中`
- `發布失敗`
- `未發布`

沒有 Active Release 時，版號顯示 `—`，狀態顯示 `未發布`。列表只呈現目前快照，完整 Release 狀態與歷程由環境與發布頁顯示。

### 5.2 測試

測試環境供開發與 QA 快速驗證，可顯示：

- `未部署`
- `部署中`
- `已部署`
- `部署失敗`

遊戲列表不直接操作 Test；具權限的編輯者可由環境與發布頁建立 Test Release、替換 build 與重新驗證。Test 永遠不納入正式 Game Round、財務、監控或風控。

## 6. 版本顯示與新版本提示

- 正式 / DEMO 版號代表該環境目前 Active Release 所指向的 Version；Release ID 在詳情中另外呈現。
- 測試版號代表 Test 目前 Active Release 或最新驗證中的 Version，不把 build ID 當版號。
- Version 是程式、數值、設定、素材與相容性快照；Artifact 是不可變執行產物；Release 是一次環境發布事實。
- RTP、限額、幣別倍率、程式或核心素材異動，必須建立新 Version／Artifact 並重新驗證，不得原地修改已發布內容。
- DEMO 與 Production 必須使用同一候選 Artifact 依序晉級；Production 不得重新 build。環境在不同時間可有不同 Active Release。
- 各環境獨立判斷是否有新的 Candidate／Release。
- 若有較新候選已通過必要檢查但尚未成為 Active，在對應版號旁顯示 `＋` 提示。
- `＋` 不取代目前生效版號，只表示有新 Release 可查看或啟用。
- 沒有新 Release 時不顯示提示。

環境與發布頁尚未完成前，版號與狀態的導頁互動先保留，不提前實作。

## 7. RTP 顯示與 Tips

列表主欄位只顯示實際 RTP，例如：

```text
96.08%
```

正式 RTP 與 DEMO RTP 的標題右側各提供一個小型資訊圖示。Tips 顯示內容至少包含：

- 理論 RTP
- 實際 RTP
- 偏差
- 統計局數
- 統計時間區間
- 最後更新時間
- RTP 監控狀態

RTP 監控狀態只在 Tips 中顯示，不另外增加列表欄位。測試環境第一階段不顯示 RTP 欄位。

## 8. Provider 全域可用性

全域可用性是 Game 層級狀態，與 Production Release 結果分開，正式值如下：

- `unpublished`：未上架
- `available`：已上架
- `maintenance`：維護中
- `suspended`：已暫停
- `retired`：已退役

例如：

```text
Production Release：已生效 v2.4.1
全域可用性：維護中
```

點擊全域可用性導向環境與發布頁。`maintenance`、`suspended`、`retired` 阻擋新 Launch；發布、回滾或狀態切換不改寫既有 Game Round。Production 發布成功不自動把 Game 切成 `available`。

## 9. GGAP 同步

GGAP 同步欄位只表示 Game、Active Version／Release 與全域可用性事件的投遞／ACK 狀態，不代表代理商個別開關，也不代表平台對帳狀態。

建議狀態為：

- `已同步`
- `同步中`
- `同步失敗`
- `尚未同步`

點擊同步狀態，未來導向 GGAP 對接頁查看詳細同步與錯誤資訊。

## 10. 快速連結與操作

- 正式 / DEMO 版號：未來導向環境與發布頁，帶入 `gameId` 與 `environment`。
- 正式 / DEMO 狀態：未來導向對應環境的發布詳情。
- 新 Release `＋` 提示：未來導向對應環境的可啟用版本詳情。
- 全域可用性：導向環境與發布頁並帶入 `game_id`。
- GGAP 同步：未來導向 GGAP 對接頁。
- 操作欄：固定提供「詳情」。

詳情頁預留顯示：

- 正式、DEMO、測試三個環境摘要
- 各環境版本與狀態
- RTP 資訊
- Provider 全域可用性
- GGAP 同步狀態
- 設定完整度區塊或分頁

設定完整度檢查項目尚未定案，先保留擴充位置，不在本文件固定檢查清單。

素材上傳結果不列入遊戲詳情頁的本次範圍，素材由獨立資產管理頁處理。

## 11. 篩選、排序與分頁

### 篩選

- 遊戲代號 / 名稱
- 遊戲類型
- 正式狀態
- DEMO 狀態
- 測試狀態
- 全域可用性
- GGAP 同步狀態
- RTP 監控狀態

### 排序

預設依遊戲 ID 排序。後續可支援：

- 遊戲名稱
- 最後更新時間
- RTP
- 正式環境狀態

### 分頁

- 每頁 10 筆

## 12. 視覺呈現

狀態使用低飽和、淡色背景搭配深色文字，不使用鮮豔高飽和色。

建議方向：

| 類型 | 顏色方向 |
|---|---|
| 上架、正常、已同步 | 淡綠 |
| 維護中 | 淡琥珀 |
| 暫停新局 | 淡橘灰 |
| 已部署、部署中、同步中 | 淡藍或藍灰 |
| 未啟用、未部署、尚未同步 | 淡灰 |
| 部署失敗、同步失敗 | 淡紅 |
| 新 Release 提示 `＋` | 淡琥珀或淡藍 |

RTP 主數值保持中性色，監控狀態只在 Tips 中使用淡色提示。

## 13. 非本頁範圍

- 代理商或商戶個別開關
- Release 啟用與回滾
- 遊戲規則、RTP、限紅的完整編輯
- 素材上傳與素材同步
- 報表匯出
- 手機版列表
