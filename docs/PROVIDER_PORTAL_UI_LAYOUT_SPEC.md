# Provider Portal 共用頁面版型規範

> 版本：0.1.0
> 更新日期：2026-08-09
> 狀態：目前原型版型規則；後續頁面製作與調整的共同依據

本文件定義 Provider Portal 原型各類頁面的外層寬度、內容起始位置與 Placeholder 說明區塊使用方式。目的不是限制每個頁面的內容設計，而是讓不同開發 Session 產出的頁面維持一致的閱讀寬度、資訊密度與版型邏輯。

## 1. 共用原則

- 頁面內容應以主內容區可用寬度為基準，不額外建立會造成左右留白不一致的固定畫布。
- `max-width` 只在內容型態確實需要時使用，不作為所有頁面的全域預設。
- 頁面標題與麵包屑由主框架提供；頁面內不要重複建立相同的導覽標題區。
- 已經有實際查詢、摘要卡、列表、圖表或編輯內容的頁面，應直接從主要工作內容開始。
- Placeholder 說明只能協助確認尚未定稿頁面的責任與內容方向，不應與實際報表內容重複。

## 2. 外層內容寬度

### 2.1 1500px 寬版頁

以下頁面使用 `max-width: 1500px`，並在桌機版置中；窄版時應自然縮小至主內容區寬度：

| 頁面群組 | 頁面 | 實作對應 |
|---|---|---|
| 遊戲管理 | 遊戲列表 | `.provider-games-page` |
| 遊戲管理 | 環境與發布 | `.provider-placeholder-page--wide`，只套用於 `GameEnvironments` |
| 遊戲監控與風控 | 監控總覽 | `.provider-placeholder-page--wide`，只套用於 `ProviderMonitoring` |
| 官方網站 | Banner 管理、法務與聯絡資訊、發布與版本紀錄 | `.website-page` |
| 遊戲大廳 | 大廳總覽、遊戲清單、遊戲管理、DEMO環境數據、大廳預覽 | `.lobby-page` |

1500px 是桌機版內容框架的上限，不代表內部每個卡片、欄位或表格都必須固定寬度。內部區塊仍應使用 grid、flex、表格水平捲動與響應式斷點處理。

### 2.2 不設定頁面最大寬度

以下頁面不設定頁面層級的 `max-width` 或 `margin: 0 auto`，直接使用主內容區可用寬度：

| 頁面 | 原因 |
|---|---|
| 遊戲紀錄 | 欄位較多，讓查詢區與單筆 Game Round 列表取得完整可用寬度 |
| 財務總覽 | 統計卡、趨勢圖與財務資訊需要依主內容區伸展 |
| 代理商 × 遊戲彙總 | 彙總表與匯出欄位較多，避免額外固定寬度限制 |
| 遊戲設定 | 以內容區塊與設定表單自身的欄位規則控制寬度 |
| 數值設定 | 以摘要卡、監控圖表與設定表格自身的欄位規則控制寬度 |
| 遊戲版本 | 以版本列表與操作欄位自身的欄位規則控制寬度 |
| 遊戲素材 | 以素材管理區塊與列表自身的欄位規則控制寬度 |

「不設定最大寬度」不等於內容無限制放大；主框架的左右 padding、內部卡片比例、表格 overflow 與響應式規則仍然有效。

## 3. Placeholder 說明區塊

共用 Provider Placeholder 原本可包含以下三種說明區塊：

1. Hero：頁面用途與 Prototype / Mock data 標示。
2. 頁面資訊：功能說明與責任範圍。
3. 主要內容區塊：以 blueprint 卡片預告預計製作的內容。

使用規則如下：

- 尚未開始討論內容的 Placeholder 頁面，可以保留三種區塊，作為規格討論與頁面範圍提示。
- 已完成主要內容規劃，且頁面已有摘要卡、查詢條件、列表、圖表或操作內容時，應移除重複的 Hero、頁面資訊與主要內容區塊。
- 實際報表頁應從主要工作內容開始，不要讓說明卡片排在報表資料之前。
- 監控總覽與環境與發布目前採用此規則：移除說明區塊，直接從監控摘要卡或環境摘要資料開始。風控報表與風控告警／處理已有完整內容，直接從摘要卡、查詢、列表或處理工作區開始，不保留 Placeholder blueprint。
- 移除說明區塊時，不能一併移除摘要卡、資料列表、空資料狀態或後續 API 待接資訊，除非該頁規格另有決定。

## 4. 響應式要求

- 桌機版使用頁面指定的 1500px 上限或主內容區完整寬度。
- 當可用寬度不足時，頁面不得產生水平溢出；欄位應重排、收縮或由表格容器提供水平捲動。
- 不以 viewport 寬度直接縮放主要文字；標題、卡片與表格需依既有斷點調整排列。
- 1500px 寬版與流動寬度頁面都必須在窄版保留查詢、檢視與主要操作的可用性。

### 4.1 繁體中文優先與技術值保留

- Provider Portal 主要介面文字使用台灣繁體中文；英文只作為技術值、原始欄位名稱、協定資訊或選項輔助。
- 表格欄位、摘要卡與狀態標籤使用簡潔中文；下拉與單選選項可使用「中文（English）」格式，避免將同一組中英雙語 mapping 套用到每一列資料。
- `Risk Event`、`Game Round`、`Provider`、`Launch`、`Settle`、`Callback`、`Request`、`Response`、`Error message` 與 `Tips` 分別以風控事件、遊戲回合、供應商、啟動、結算、回呼、請求、回應、錯誤訊息與提示為主要顯示文字。
- Production、DEMO 可顯示為「正式環境（Production）」、「展示環境（DEMO）」；Info、Low、Medium、High、Critical 可顯示為「資訊（Info）」、「低（Low）」、「中（Medium）」、「高（High）」、「嚴重（Critical）」。Test 不應出現在 Provider 風控頁面。
- API 值、路由、ID、錯誤碼、HTTP 狀態碼、版本號、原始欄位名稱與協定 endpoint 不得翻譯或改值。英文遊戲名稱沒有官方中文名稱時維持原文；mock 證據的說明文字可翻譯，但需保留必要協定資訊。

## 5. 後續實作檢查清單

新增或調整頁面時，先確認：

- 這個頁面屬於 1500px 寬版，還是應使用主內容區完整寬度？
- 是否已經有實際主要內容？若有，是否還保留重複的說明 Hero、頁面資訊或 blueprint？
- 頁面標題是否已由主框架提供，頁面內是否重複顯示？
- 查詢區、摘要卡、圖表與列表在桌機及窄版是否能維持清楚的閱讀順序？
- 表格欄位較多時，是否以容器捲動或欄位重排處理，而不是再增加第二層固定寬度？

## 6. 目前程式對應

- 1500px 寬版共用樣式：`src/views/GameWebsite/website.css`、`src/views/GameLobby/game-lobby.css`、`src/views/Games/Index.vue`、`src/views/Provider/Placeholder.vue`。
- 財務總覽與代理商 × 遊戲彙總已移除頁面外層固定最大寬度：`src/views/Finance/Overview.vue`、`src/views/Finance/AgentGames.vue`。
- 遊戲紀錄頁未設定額外頁面最大寬度：`src/views/Reports/ProviderGameRounds.vue`。
- Placeholder 說明區塊與監控總覽路由判斷位於：`src/views/Provider/Placeholder.vue`。
- 風控報表內容位於：`src/views/Provider/RiskReports.vue`；風控告警／處理內容位於：`src/views/Provider/RiskAlerts.vue`。告警工作台不設定頁面層級固定最大寬度，16 欄佇列由表格容器提供水平捲動。
